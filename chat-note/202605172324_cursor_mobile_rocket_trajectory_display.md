**Cursor**

모바일에서 로켓 궤적이 어긋나는 문제를 조사합니다. 관련 코드부터 확인합니다.


원인은 궤적(SVG 픽셀)과 로켓(CSS `vw`/`vh`)이 서로 다른 뷰포트 기준(`innerWidth` vs `clientWidth`, 모바일 `vh` 변화)을 쓰는 것으로 보입니다. 공통 뷰포트 메트릭으로 통일하겠습니다.


뷰포트 기준을 `rocket-travel` 컨테이너 크기로 통일하고, 궤적 Y좌표를 `vh` 비율로 저장해 모바일 주소창 변화에도 맞춥니다.


로켓 위치도 궤적과 동일한 픽셀 기준으로 맞춥니다.


**원인:** 로켓은 CSS `vw`/`vh`, 궤적은 `window.innerWidth`/`innerHeight` 픽셀로 그려져 모바일에서 기준이 달랐습니다. `100vw`와 실제 스크롤 폭 차이, 주소창 표시/숨김으로 `vh`가 바뀌는 것도 겹쳤습니다.

**수정 요약:**

1. **`viewportMetrics()`** — `.rocket-travel` 컨테이너 크기를 로켓·궤적 공통 기준으로 사용  
2. **로켓 위치** — `vw`/`vh` 대신 같은 기준의 `px`로 배치  
3. **궤적** — Y좌표를 `vh` 비율로 저장하고, 그릴 때마다 현재 뷰포트 높이로 환산  
4. **스크롤 페이지** — `100vw` → `100%`로 바꿔 가로 스크롤 폭과 좌표계 일치  
5. **3D 지구 인트로** — `clientWidth`/`clientHeight`로 투영  
6. **`visualViewport` resize/scroll** — 모바일 주소창 변화 시 궤적·로켓 재정렬  

변경 파일: `scroll.js`, `line.js`, `rocket.js`, `base.css`, `earth/page.js`, `nav-menu.js`

배포 전 `node build_publish.js`로 `publish/`를 다시 빌드한 뒤, 실제 기기에서 지구 궤적·거리 화면·달 궤적이 로켓과 맞는지 확인해 주세요.
